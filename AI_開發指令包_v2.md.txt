第一部分：共用 Context（每個 session 都要貼）
我正在參加 24 小時黑客松，時間極度緊迫。請直接寫可執行的完整程式碼，不要問我要不要開始、不要給多個方案讓我選、不要留 TODO 空白。有不確定的地方，選一個合理預設值往下做，最後用一行標註你的假設。
專案定位（很重要，會影響你怎麼寫程式）
涼路 CoolPath 是一個熱暴露評估引擎，不是一個導航 App。


核心產品是 /api/coolRoute 這支 API：輸入起點終點，回傳多條路線及其熱暴露分數。網站只是這支 API 的第一個客戶端，導航本身完全交給 Google Maps。


因此：


* API 的回傳格式要乾淨、可讀，能直接在瀏覽器打開展示給人看
* 網站不做 turn-by-turn 導航，只做「決定走哪條」然後跳轉到 Google Maps
* 不要為了讓網站功能豐富而把邏輯寫進前端，邏輯一律放在 Cloud Functions
技術棧（不要更換）
* 前端：純 HTML + vanilla JavaScript，無框架、無 build 工具
* 地圖：Google Maps JavaScript API
* 語音：Web Speech API (speechSynthesis)
* 推播：FCM Web Push + Service Worker
* 後端：Firebase Cloud Functions（Node.js 20）
* 資料庫：Firestore
* AI：Gemini API
* 路線：Google Maps Routes API
* 地表溫度：Earth Engine 預先算好的靜態 GeoJSON，不做即時運算

誠實性守則（違反會在評審問答被拆穿，比功能少更嚴重）
事實
	因此
	地表溫度來自 Landsat 熱紅外，原生解析度 100 公尺
	可比較「不同路廊」，不可宣稱能分辨「同一條路的兩側」
	熱圖是 2023–2026 夏季影像的中位數，是氣候常態
	不可顯示為「即時溫度」或「現在的溫度」。標示為「夏季平均地表溫度」
	Landsat 過境時間固定約上午 10:30
	資料代表上午時段，不是午後最熱時刻
	紫外線來自環境部測站，台北僅一至兩站
	城市級單一數值，不可沿路線變化，不可參與路線評分
	熱傷害數據未涵蓋所有醫療院所
	稱「監測數據」，不可稱「全國人數」
	

UI 文案不可出現：「即時地表溫度」、「這條路現在 42 度」、「紫外線路線規劃」、「精準到每一公尺」。


UI 文案應該長這樣：「夏季平均地表溫度 42°C」、「資料來源：Landsat 8/9 熱紅外，100m 網格」。

第二部分：任務指令
任務 D — 熱暴露評分引擎（Frank）｜最高優先，這是核心產品
寫 Cloud Function coolRoute，接收 {origin, destination, mode}，回傳 RouteOption[]。


支援 GET 查詢字串，讓人可以直接在瀏覽器打開看 JSON：


/api/coolRoute?origin=24.9874,121.5759&destination=25.0488,121.5137&mode=driving
實作
注意：Routes API 不支援自訂多邊形迴避或自訂成本函數（僅有 avoidTolls / avoidHighways / avoidFerries / avoidIndoor）。評分演算法必須自行實作。


1. 呼叫 Routes API computeRoutes，設 computeAlternativeRoutes: true
   * Field mask 需含 routes.polyline.encodedPolyline、routes.duration、routes.distanceMeters
   * travelMode 給 DRIVE（機車無專屬選項）
2. 解碼每條 polyline 還原座標序列
3. 沿線每 50 公尺取樣一點
4. 每個取樣點查 LST 網格（functions/data/taipei_lst_grid.geojson），求平均與最大值
5. heatScore 最低者標 coolest，durationSec 最短者標 fastest（可為同一條）
6. 為每條路線產生 mapsUrl（見下）
7. 依 heatScore 排序回傳
mapsUrl 產生方式
從該條路線的 polyline 均勻取 3–5 個中繼點（Google Maps URL 的 waypoints 上限為 9），組成：


https://www.google.com/maps/dir/?api=1
&origin={lat},{lng}
&destination={lat},{lng}
&waypoints={lat},{lng}|{lat},{lng}|{lat},{lng}
&travelmode=driving

⚠️ 產生後必須人工實測：點開連結，確認 Google 重現出來的路線與原本算的最涼路線吻合。若偏離，增加中繼點密度。
共用模組
把 LST 查詢抽成 functions/lst.js：


// 啟動時載入 GeoJSON 到記憶體一次
function lookupSurfaceTemp(lat, lng)  // number | null，超過 500m 無資料回傳 null

任務 C — Gemini 判斷層（Lin）
寫 Cloud Function decide，接收 RiskAssessment 與 RouteOption[]，呼叫 Gemini API 回傳 AgentDecision。


這是 Agent 的核心，重點是「決策」不是「生成文字」。 System prompt 必須要求 Gemini：


* 從所有訊號中只挑出此刻最重要的一件事來講，不要條列所有指標
* action 必須具體且含數字（「多花 5 分鐘，低 6 度」），不可是「請多加注意」這類空話
* level 為 low 時 shouldNotify 必須為 false —— 系統要能判斷不打擾使用者
* speech 為口語化短句，30 字內。數字用國字（「四十二度」而非「42度」，避免 TTS 讀錯）
* 補水建議只能是白開水或電解質飲料
* 不可宣稱地表溫度是即時值


要求 Gemini 只輸出 JSON、不加 markdown 圍欄。解析前先 strip 掉可能的 ```json 標記，用 try/catch 包住 JSON.parse，失敗時回傳規則式的預設 decision。

附錄：Earth Engine 前處理腳本
於 code.earthengine.google.com 執行。Earth Engine 沒有 API key，用 OAuth 登入，右上角選到已註冊的 Cloud project 即可。


var taipei = ee.Geometry.Rectangle([121.45, 24.95, 121.67, 25.21]);


function prep(img) {
  var lst = img.select('ST_B10')
    .multiply(0.00341802).add(149.0).subtract(273.15)   // Kelvin → 攝氏
    .rename('LST');
  var qa = img.select('QA_PIXEL');
  var mask = qa.bitwiseAnd(1 << 3).eq(0)                // 去雲
              .and(qa.bitwiseAnd(1 << 4).eq(0));        // 去雲影
  return lst.updateMask(mask);
}


var col = ee.ImageCollection('LANDSAT/LC08/C02/T1_L2')
  .merge(ee.ImageCollection('LANDSAT/LC09/C02/T1_L2'))
  .filterBounds(taipei)
  .filterDate('2023-06-01', '2026-09-30')
  .filter(ee.Filter.calendarRange(6, 9, 'month'))       // 僅夏季
  .filter(ee.Filter.lt('CLOUD_COVER', 30))
  .map(prep);


var lst = col.median().clip(taipei);


Map.centerObject(taipei, 11);
Map.addLayer(lst, {min: 26, max: 44,
  palette: ['#2c7bb6','#abd9e9','#ffffbf','#fdae61','#d7191c']}, 'LST');


var grid = lst.sample({region: taipei, scale: 200, geometries: true});
Export.table.toDrive({
  collection: grid,
  description: 'taipei_lst_grid',
  fileFormat: 'GeoJSON'
});

驗證：圖層數值應落在約 28–45°C。若出現三百餘之值為未減 273.15；若整片空白則放寬日期範圍或雲量門檻。


匯出後把 GeoJSON 同時放進 public/data/ 與 functions/data/。
